# Ground rules

This repository is the only channel between the planning session and the compute node. The PI controls what happens by merging pull requests.

## Who does what

| Role | Does | Does not |
| --- | --- | --- |
| **PI** (repository owner) | Decides. Approves by merging a pull request. | |
| **Planning session** | Literature review, paper plans, experiment briefs, analysis of returned results, paper drafts. | Run experiments. |
| **Compute node** (Claude Code with GPU access) | Runs experiments and returns results. | Run anything whose brief is not on `main`. |

## The gate

1. Nothing reaches `main` except through a pull request merged by the PI.
2. An experiment may run only if its brief is in `briefs/` on `main`.
3. The node runs a brief as written. If a step cannot be done as written, the node stops and reports it in the results pull request. It does not improvise.
4. Results come back as a pull request from the node. A number may enter a paper only after its results pull request is merged.

## Flow

`paper plan` → `experiment brief` → **PI merges** → node runs → `results` pull request → **PI merges** → analysis → next brief

## Where things go

| Path | Contents |
| --- | --- |
| `litreview/` | Reviews with their search logs, source index and evidence ledger |
| `paper1/`, `paper2/` | Plan, outline, drafts and figures for each paper |
| `briefs/` | One file per experiment, named `P<paper>-E<nn>-<short-name>.md` |
| `results/<brief-id>/` | What the node returns for that brief |

## What never goes in the repository

- Datasets and model weights. Record the source URL, version, checksum and licence instead.
- Tokens, passwords, keys or any other credential.
- Personal data.

This repository is currently public: treat everything committed here as published.

## Commits and pull requests

- No AI co-author lines and no "generated by" lines, in commits or in pull requests.
- One brief per pull request.
- Branch prefixes: `setup/`, `lit/`, `plan/`, `brief/`, `results/`, `paper/`.
- Never force-push to `main` or rewrite its history.

## Minimum contents of a results package

| File | Contents |
| --- | --- |
| `RESULTS.md` | What ran, headline numbers, deviations from the brief, anything that failed |
| `metrics/` | Raw per-run metrics as CSV or JSON: every seed, not only means |
| `config/` | Exact configuration files and command lines |
| `env.txt` | Commit hash of the code that ran, hardware, OS, package versions |
| `logs/` | Run logs |
| `figures/` | Each plot together with the script and data that produced it |
| `assets.md` | Datasets and weights used: source, version, checksum, licence |
