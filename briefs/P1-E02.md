## Questions

1. How does positioning error grow as fewer reference points are surveyed?
2. How does it grow when access points go missing after the survey?

## Why it matters

These are the two stress tests of the paper. Question 1 feeds Fig. 2a and may give the headline number (survey effort saved). Question 2 feeds Fig. 2b and tests whether native handling of missing values helps.

## Setup

Everything not stated here is as in `P1-E01`: data, inputs, targets, the two ways of writing "not detected", model definitions, search spaces, tuning objective, metrics.

- **Configurations:** CETC331, HCXY-All and SYL-All.
- **Models:** `tabpfn-nan`, `tabpfn-ph`, `tabicl`, `knn`, `rf`, `lgbm-ph`, `lgbm-nan`, `svr`, `mlp`, `gp`.
- **Test data:** always the full test file of the configuration.

## Procedure

### Part A. Fewer reference points (E2)

1. Shares of reference points kept: 5, 10, 25, 50 and 100%. The number kept is the share times the number of reference points, rounded up:

   | Config | 5% | 10% | 25% | 50% | 100% |
   |---|---|---|---|---|---|
   | CETC331 | 48 | 96 | 239 | 478 | 955 |
   | HCXY-All | 19 | 38 | 95 | 190 | 379 |
   | SYL-All | 15 | 30 | 74 | 148 | 296 |

2. Draws: 10 per configuration, numbered 0 to 9. For draw `d`, shuffle the reference points with seed `d` and keep the first ones, so that within a draw each smaller survey is contained in the larger one. The 100% share is the same for all draws: run it once and reuse the `P1-E01` result where the model and seed match.
3. The reduced survey is every training row of the kept reference points. For TabPFN on HCXY at 100%, apply the 10,000-row cap exactly as in `P1-E01`.
4. For each configuration, share and draw:
   - re-run the Optuna search (30 trials, seed 0, 3-fold `GroupKFold` by reference point) for `knn`, `rf`, `lgbm-ph`, `lgbm-nan`, `svr` and `mlp` on the reduced survey only, then refit on the whole reduced survey with seed `d`;
   - fit `gp` on the reduced survey;
   - fit `tabpfn-nan`, `tabpfn-ph` and `tabicl` with the reduced survey as context, seed `d`;
   - predict the full test file with every model.
5. For every test row record, besides the prediction and the positioning error, whether its location is among the kept reference points (this matters in CETC331).
6. Write `metrics/e2_summary.csv`: configuration, share, number of reference points, draw, model, the five error statistics, fit and predict seconds.
7. Write `metrics/e2_crossing.csv`: for each configuration and each tabular foundation model, the smallest share at which its mean error (averaged over draws) is at or below the mean error of tuned `knn` at 100%, found by linear interpolation between the shares on a logarithmic share axis. Write "not reached" if it never is.

### Part B. Access points that go missing after the survey (E3)

8. Models are fitted once per configuration on the whole training file, with seed 0 and, for the baselines, the best values from `P1-E01`. The training data is never changed in this part.
9. Shares of access points switched off: 0, 10, 20, 30, 40, 50 and 60% of the MAC columns of the configuration, rounded up.
10. Draws: 10 per configuration, numbered 0 to 9. For draw `d`, shuffle the MAC columns with seed `d` and switch off the first ones, so that within a draw each smaller set is contained in the larger one. The 0% share is run once.
11. Switching off a column means: in every test row, that column is set to "not detected", written the way the model expects (NaN or `-105`).
12. Predict the altered test file with every model. To save time, the altered copies of a test file may be stacked and predicted in one call.
13. Write `metrics/e3_summary.csv`: configuration, share, number of columns switched off, draw, model, the five error statistics.

### Part C. Report

14. Save per-row predictions for both parts in `metrics/predictions/` as compressed CSV.
15. Draw two draft figures, one panel per configuration plus one panel averaged over the three:
    - `figures/e2_reference_points`: mean error against share of reference points (logarithmic horizontal axis), one line per model, band from the lowest to the highest draw;
    - `figures/e3_missing_aps`: mean error against share of access points switched off, same style.
    Save each as PDF and PNG.
16. Write `RESULTS.md`: one table per configuration for each part (mean and standard deviation over draws); the crossing table; time taken; anything that did not go as written.

## Compute estimate

Up to one day of wall-clock time on one GPU and 16 or more CPU cores; less with several GPUs. Part A is dominated by the searches on CPU, which may run in parallel across configurations, shares and draws. Disk: under 5 GB.

## Stop conditions

Stop, commit what exists, open the pull request and report, if any of these happens:

- The `P1-E01` gate has not passed.
- A model fails with an error that the fallbacks in `P1-E01` do not cover.
- Total wall-clock time passes 48 hours.

If a library call differs from what is written here, use the equivalent call and record the change in `RESULTS.md`. Do not change the procedure.
