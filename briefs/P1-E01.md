## Question

With the full survey of a building as context, does an off-the-shelf tabular foundation model localize as well as tuned classical methods, and what does it cost in time and memory?

## Why it matters

This is the main result of the paper. It feeds Table I. The pipeline check (Part A) is a gate: nothing else runs until it passes.

## Setup

### Data

SODIndoorLoc. Clone `https://github.com/bijingxue/SODIndoorLoc` into `data/SODIndoorLoc` (the `data/` folder is ignored by git) and record the commit hash. The repository has no licence file; its README asks for a citation of Bi et al., Satellite Navigation 3:25 (2022).

Five configurations:

| Config | Training file | Test file | Train rows | Reference points | RSS columns | Test rows | Test points |
|---|---|---|---|---|---|---|---|
| CETC331 | `CETC331/Training_CETC331.csv` | `CETC331/Testing_CETC331.csv` | 955 | 955 | 52 | 840 | 84 |
| HCXY-All | `HCXY/Training_HCXY_All_30.csv` | `HCXY/Testing_HCXY_All.csv` | 11,370 | 379 | 347 | 860 | 86 |
| HCXY-AP | `HCXY/Training_HCXY_AP_30.csv` | `HCXY/Testing_HCXY_AP.csv` | 11,370 | 379 | 56 | 860 | 86 |
| SYL-All | `SYL/Training_SYL_All_30.csv` | `SYL/Testing_SYL_All.csv` | 8,880 | 296 | 363 | 1,020 | 102 |
| SYL-AP | `SYL/Training_SYL_AP_30.csv` | `SYL/Testing_SYL_AP.csv` | 8,880 | 296 | 46 | 1,020 | 102 |

Facts about the files:

- The last eight columns are metadata: `ECoord`, `NCoord`, `FloorID`, `BuildingID`, `SceneID`, `UserID`, `PhoneID`, `SampleTimes`. Every other column is one MAC address; its value is the signal strength in dBm.
- The value `100` means "not detected".
- A reference point is one unique (`ECoord`, `NCoord`, `FloorID`). A test point is defined the same way in the test file.
- Do not use the `_Avg` training files.

### Inputs and targets

- Inputs: the MAC columns only. No metadata column is ever an input.
- Targets: `ECoord` and `NCoord`, in metres.
- "Not detected" is written in one of two ways, depending on the model (see the model table):
  - **missing**: `100` becomes NaN;
  - **placeholder**: `100` becomes `-105`.

### Models

Tabular foundation models. Default settings, no tuning, one regressor per coordinate, GPU.

| Name | Model | Not detected | Notes |
|---|---|---|---|
| `tabpfn-nan` | TabPFN v2 | missing | `TabPFNRegressor.create_default_for_version(ModelVersion.V2, ...)` from `tabpfn`. The random seed is the run seed |
| `tabpfn-ph` | TabPFN v2 | placeholder | Same model |
| `tabicl` | TabICLv2 | missing; placeholder if the library rejects NaN | `TabICLRegressor` from `tabicl`, default checkpoint |

- TabPFN context is capped at 10,000 rows. Only HCXY exceeds it: keep 26 of the 30 scans of every reference point, drawn at random with the run seed (9,854 rows). The other configurations use every row.
- TabICLv2 uses every row. If it runs out of memory, give it the same capped context as TabPFN and say so in `RESULTS.md`.
- Use TabPFN version V2 only. Do not use any later TabPFN version, and do not accept any licence prompt.

Baselines.

| Name | Method | Not detected | Preprocessing | Tuned by |
|---|---|---|---|---|
| `knn` | `KNeighborsRegressor` | placeholder | none | Optuna |
| `rf` | `RandomForestRegressor` | placeholder | none | Optuna |
| `lgbm-ph` | LightGBM, one model per coordinate | placeholder | none | Optuna |
| `lgbm-nan` | LightGBM, one model per coordinate | missing | none | Optuna |
| `svr` | `SVR` with RBF kernel, one model per coordinate | placeholder | inputs standardised | Optuna |
| `mlp` | `MLPRegressor`, two outputs | placeholder | inputs and targets standardised | Optuna |
| `gp` | `GaussianProcessRegressor`, one model per coordinate | placeholder | fitted on one fingerprint per reference point (mean of its scans after the placeholder is applied); inputs standardised; `normalize_y=True` | its own marginal likelihood |

Search spaces (Optuna, TPE sampler, seed 0, 30 trials per baseline and configuration):

| Baseline | Search space |
|---|---|
| `knn` | `n_neighbors` 1 to 30; `weights` uniform or distance; `metric` euclidean or manhattan |
| `rf` | `n_estimators` 200 or 500; `max_features` sqrt, 0.3, 0.5 or 1.0; `min_samples_leaf` 1 to 10; `max_depth` none, 10, 20 or 30 |
| `lgbm-ph`, `lgbm-nan` | `n_estimators` 200 to 1500; `learning_rate` 0.01 to 0.2 (log); `num_leaves` 8 to 128; `min_child_samples` 1 to 50; `subsample` 0.5 to 1.0 with `subsample_freq` 1; `colsample_bytree` 0.3 to 1.0; `reg_lambda` 0.001 to 10 (log). Both coordinates share one set of values |
| `svr` | `C` 0.1 to 1000 (log); `gamma` 0.0001 to 1 (log); `epsilon` 0.01 to 1 (log). Both coordinates share one set of values |
| `mlp` | `hidden_layer_sizes` (256), (256, 128), (512, 256) or (256, 128, 64); `alpha` 1e-6 to 1e-2 (log); `learning_rate_init` 1e-4 to 1e-2 (log); `early_stopping=True`; `max_iter=1000` |
| `gp` | Kernel `ConstantKernel * RBF + WhiteKernel`, one length scale; `n_restarts_optimizer=3`. No Optuna |

Tuning objective: mean positioning error, averaged over 3 folds of `GroupKFold` on the training file, with the reference point as the group. The test file is never used for tuning.

### Metrics

- Positioning error of one test row: Euclidean distance in metres between the predicted and the true (`ECoord`, `NCoord`).
- Per configuration, model and seed: mean, median, 75th percentile, 95th percentile, and root mean square of the positioning error over all test rows.
- Cost per configuration, model and seed: wall-clock seconds to fit, wall-clock seconds to predict the test file, and for GPU models the peak GPU memory.

### Seeds

Seeds 0 to 4 for `tabpfn-nan`, `tabpfn-ph`, `tabicl`, `rf`, `lgbm-ph`, `lgbm-nan` and `mlp`. One run for `knn`, `svr` and `gp`, which have no randomness.

## Procedure

### Part A. Pipeline check (gate)

1. Set up the environment: `tabpfn==10.0.0`, `tabicl==2.2.0`, and current versions of `scikit-learn`, `lightgbm`, `optuna`, `numpy`, `pandas`, `torch` with CUDA. Write `env.txt` (Python version, `pip freeze`, GPU model, driver, CPU model, core count).
2. Clone the dataset. Check every row count, column count, reference-point count and test-point count against the table above. If any differs, stop.
3. Run `KNeighborsRegressor(n_neighbors=5, weights="distance", metric="euclidean")`, with both coordinates as targets, on CETC331, HCXY-All and SYL-All. Do it twice: once with `100` left as it is, once with the placeholder `-105`.
4. For each of the six runs compute the mean, 50th, 75th and 95th percentile of the positioning error, and also the mean absolute error per coordinate averaged over the two coordinates.
5. Compare with the dataset paper:

   | Config | Mean (m) | 50th (m) | 75th (m) | 95th (m) |
   |---|---|---|---|---|
   | CETC331 | 2.876 | 2.316 | 3.803 | 6.307 |
   | HCXY-All | 2.365 | 1.470 | 3.231 | 6.627 |
   | SYL-All | 4.656 | 3.842 | 6.078 | 8.521 |

6. The gate passes if, for one of the two ways of writing "not detected", the mean positioning error is within 0.05 m of the paper for all three configurations. Write the full comparison to `metrics/e0_check.csv` and state in `RESULTS.md` which way passed.
7. If the gate does not pass, stop. Commit what you have, open the pull request, and report the comparison.

### Part B. Full-survey comparison

8. For each configuration and each tuned baseline, run the Optuna search. Save the best values to `config/best_params.json` and the full trial history to `logs/`.
9. Refit each baseline on the whole training file with its best values, once per seed, and predict the test file.
10. Fit and predict `gp`.
11. Fit and predict `tabpfn-nan`, `tabpfn-ph` and `tabicl`, once per seed.
12. Save, for every configuration, model and seed, one file with a row per test row: test-point id, true coordinates, predicted coordinates, positioning error. Put them in `metrics/predictions/` as compressed CSV.
13. Write `metrics/e1_summary.csv`: configuration, model, seed, the five error statistics, the three cost numbers.
14. For each configuration, take the tabular foundation model with the lowest mean error (averaged over seeds) and the baseline with the lowest mean error. Using seed 0 of each, compute the difference in mean positioning error with a 95% bootstrap interval: 10,000 resamples of test points, where a resampled test point brings all 10 of its rows. Write `metrics/e1_bootstrap.csv`.
15. Count, per configuration, how many test points share their location with a reference point. Report it in `RESULTS.md`.
16. Write `RESULTS.md`: the gate result; one table per configuration (mean and standard deviation over seeds for every model and statistic); the bootstrap table; the cost table; the TabICLv2 checkpoint used and how it handled NaN; anything that did not go as written.
17. Write `assets.md`: dataset commit; for each model the package version, the weight file names with SHA-256, and the licence text or licence name shipped with the weights.

## Compute estimate

About half a day of wall-clock time on one GPU and 16 or more CPU cores. Disk: under 5 GB. The GPU is needed only for the tabular foundation models; the searches run on CPU and may run in parallel.

## Stop conditions

Stop, commit what exists, open the pull request and report, if any of these happens:

- A dataset count differs from the table (step 2).
- The gate does not pass (step 6).
- The TabPFN V2 weights cannot be downloaded without accepting a licence or creating an account.
- The TabICLv2 weights carry a licence other than BSD, MIT or Apache. In that case drop `tabicl`, finish the rest, and report.
- A model fails with an error that the fallbacks written above do not cover.
- Total wall-clock time passes 24 hours.

If a library call differs from what is written here, use the equivalent call and record the change in `RESULTS.md`. Do not change the procedure.

## Out of scope

- Any other dataset, any other model, any later TabPFN version.
- Fine-tuning or tuning of the tabular foundation models.
- Using metadata columns as inputs.
- Using the test files for tuning or model selection.
- The few-reference-point and missing-access-point experiments (`P1-E02`).
- Writing paper text.
